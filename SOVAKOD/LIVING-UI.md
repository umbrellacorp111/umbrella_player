# Living UI — реактивный слой Umbrella Player

Отдельных файлов НЕТ — всё дописано в конец уже собираемых:

```
styles.css   → в конце блоки «Living UI» и «Boot screen»
app2.js      → в конце два IIFE: Living UI v1.1 и Boot screen
silk-aurora.js → добавлен метод set() для морфинга шейдера на лету
index.html   → не менялся
```

Так сделано специально: PyInstaller собирает .exe по списку файлов в .spec,
и новые файлы туда не попадали. Теперь правок в .spec не нужно.

Логика плеера не тронута: ни одна функция не переопределяется, зацепки — только
DOM-события, `MutationObserver` и уже существующий `AnalyserNode`.

## Что сделано по пунктам ТЗ

**1. Живая обложка.** Дыхание (`scale` по синусу + бас), наклон к курсору 4.5° с мягким
возвратом, ripple-волны из мини-обложки в панели на сильных ударах (в большом плеере
кругов нет — там они выглядели грязно), при смене трека — `dissolve` в блюр + разлёт частиц, затем
обратная «сборка»: частицы слетаются в точку и обложка собирается из размытия.

**2. Энергетическое поле.** `#lvAuraBar` вокруг player bar и `#lvAuraNp` вокруг сцены
Now Playing. Два слоя: внутренний следует за басом (коэффициент сглаживания 0.4),
внешний за RMS (0.06) — быстрый и медленный. Цвет из `--dyn-h`. На паузе гаснет до 35%.

**3. Текст как объект.** Название и артист собираются по буквам (blur → sharp, спринговый
easing, шаг 22 мс). `textContent` при этом остаётся исходным — совместимость с кодом,
который его читает. Активная строка lyrics: пульсирующее свечение + scale 1.16, соседние
уходят по Z с блюром по расстоянию (перспектива 900px). Время пульсирует на `--lv-beat`.

**4. Микро-реакции.** Play/pause/shuffle/repeat получают scale на бите (120–130 мс).
У прогресса появился светящийся «хвост», который догоняет заполнение (lerp 0.06).
При смене трека player bar делает короткий skewX-толчок. Иконки сайдбара подпрыгивают
в такт, если пользователь не трогал интерфейс 20 секунд.

**5. Глубина.** Открытие Now Playing уводит дашборд в blur(16px) + scale(.955).
Карточки треков при наведении поднимаются по Z на 26px с отражением снизу.
Сетки библиотеки получают перспективу: дальние карточки мельче, мягче и бледнее.

**6. След прослушивания.** Тонкая светящаяся линия вдоль верхнего края player bar растёт
вместе с прогрессом, на конце трека сворачивается в точку, а прогресс-бар «сгорает».
Прошлые следы остаются на канвасе полупрозрачными дугами (до 8 штук).

**7. Реактивный фон.** Плёночное зерно (`noise.png`) — сильнее на тихих участках.
Хроматическая аберрация по краям только в пиках. Шейдер silk-aurora морфится по
энергичности трека: `speed 0.7→1.9`, `intensity 0.85→1.4`, `grain 0→0.12`.

**8. Состояния.** Пауза: виньетка, частицы замедляются вдвое, обложка теряет насыщенность.
Конец трека: обложка уходит в чёрный, частицы улетают вверх, прогресс «сгорает».
Старт: вспышка цвета темы из-под плеера.

**9. Курсор.** Орбитальные частицы при наведении на обложку (и на мини-обложку).
Шлейф курсора убран по просьбе. Обложку в Now Playing можно потянуть мышью —
возвращается пружиной (k=0.14, damping=0.76).

**10. Мини-эффекты.** Сердечко при добавлении в избранное пружинит и взрывается частицами.
Нажатие «Скачать» запускает бегущий контур по краю карточки (снимается, когда кнопка
исчезает). Счётчики библиотеки и статистики пересчитываются odometer-анимацией.

## Настройка

Все группы отключаемы. Из консоли:

```js
LivingUI.set('cursor', false);   // сохраняется в localStorage и перезагружает страницу
LivingUI.config                  // текущее состояние
LivingUI.audio                   // живые значения bass / mid / hi / rms / energy / beat
```

Группы: `cover, aura, text, micro, depth, trail, background, states, cursor, micro2, sidebarBounce`.

Слой сам уважает:
* `prefers-reduced-motion` — тяжёлые анимации отключаются;
* настройку «Лёгкие эффекты» (`settings.lowFx`) — меньше частиц, без перспективы и шлейфа;
* настройку «Визуализация» (`settings.visualizer`) — без неё интерфейс не реагирует на звук;
* `visibilitychange` — цикл останавливается на скрытой вкладке.

## API для интеграции

```js
LivingUI.ripple(x, y, {vr, width, alpha, hue});
LivingUI.burst(x, y, count, {speed, size, hue, gravity});
LivingUI.implode(x, y, count, radius);
LivingUI.contour(cardElement, 0.42);   // прогресс по контуру, null — бесконечный бег
LivingUI.onBeat(strength => { /* ... */ });
```

## CSS-переменные на `:root`

`--lv-bass --lv-mid --lv-hi --lv-rms --lv-energy --lv-beat --lv-breathe --lv-ring-in
--lv-ring-out --lv-grain --lv-ab --lv-idle` — можно использовать в любых своих стилях.

## Замечания

* Канвас эффектов лежит на `z-index: 9990` — выше плеера и виниловой полки, ниже
  lyrics-оверлея, тостов и модалок. На виниловой полке глобальные слои скрываются.
* Наклон/дыхание обложки не применяются, пока идёт gsap-анимация открытия Now Playing
  (проверяется класс `gsap-active` и `gsap.isTweening`), чтобы не спорить за `transform`.
* Анализатор берётся существующий — второй `createMediaElementSource` на тот же
  `<audio>` браузер бы не дал.


## Стартовый экран

Показывается при каждом запуске: чёрный экран, пыль слетается в центр, вспышка,
кольцо и название с широким трекингом. Пропуск — клик или любая клавиша, всего ~4.5 с.
Тон на старте играет, только если браузер разрешил звук без жеста.

```js
localStorage.setItem('umbrella_boot','off');   // выключить
localStorage.removeItem('umbrella_boot');      // вернуть
```

## Почему эффекты «затухали» через несколько секунд

Три причины, все устранены в v1.1:

1. Реактивные переменные писались в `:root`. Кастомные свойства наследуются, поэтому
   каждый кадр пересчитывался стиль всего документа — с сотнями `.track-row` это
   быстро упирается в потолок. Теперь переменные пишутся в 5 контейнеров
   (`#playerBar`, `#nowPlaying`, `#sidebar`, `#lyricsBody`, аура) и только при
   реальном изменении значения.
2. Полноэкранный слой аберрации имел `filter: blur(6px)` и менял прозрачность каждый
   кадр — это перерисовка всего экрана с блюром 60 раз в секунду. Блюр убран,
   прозрачность обновляется только при заметном изменении.
3. Оттенок темы читался через `getComputedStyle` на каждую частицу. Теперь один раз за кадр.

Дополнительно: сторож перезапускает цикл, если кадры перестали идти, а при просадке
FPS слой сам себя ужимает (`LivingUI.quality` 0→1→2) вместо фриза. `LivingUI.fps`
покажет текущую частоту.

## Про запуск без сервера

Если открыть `index.html` двойным кликом, бэкенда нет — трек не играет, `AnalyserNode`
отдаёт нули, и всё «звуковое» (дыхание, аура, биты, хвост) естественно замирает.
Проверять надо через обычный запуск плеера.

# v1.2 — что изменилось

## Реактивность больше не зависит от чужих условий

Раньше слой ждал, пока `app2.js` сам поднимет `AnalyserNode`, и дополнительно
проверял настройку «Визуализация». Если она выключена или `AudioContext` остался
в состоянии `suspended`, анализатор отдавал нули — и интерфейс выглядел мёртвым.

Теперь слой сам вызывает `ensureAnalyser()`, сам делает `audioCtx.resume()` при
каждом `play`, клике и нажатии клавиши, и повторяет попытку раз в 1.5 секунды,
пока играет трек. Настройка «Визуализация» на него больше не влияет.

## Ритм без анализатора

Если анализатор есть, но отдаёт только нули дольше 1.2 секунды (так бывает,
например, при кросс-доменном потоке — Web Audio в этом случае по спецификации
выдаёт тишину), включается синтетический ритм ~112 BPM: интерфейс продолжает
дышать и пульсировать. Отключается в настройках («Ритм без анализатора»).

## Диагностика

Настройки → Живой интерфейс → **Диагностика реактивности**. Панель слева сверху
показывает fps, уровень качества, есть ли анализатор, состояние `AudioContext`,
сумму спектра и живые значения bass/beat/energy с полоской.

Как читать:
* `analyser нет` — граф не поднялся, смотри ошибки в консоли;
* `ctx suspended` — браузер не разрешил звук, нужен клик по странице;
* `сумма 0` при играющем треке — анализатор подключён, но звук до него не доходит;
* всё в норме, но `bass` около нуля — трек действительно тихий на низах.

## 13 переключателей в настройках

Новая группа «Живой интерфейс» в Настройках: живая обложка, энергетическое поле,
живой текст, микро-реакции, глубина, след прослушивания, реактивный фон,
состояния, курсор и обложка, мини-эффекты, стартовая заставка, ритм без
анализатора, диагностика. Всё применяется сразу, без перезапуска, и хранится в
`localStorage` под ключом `umbrella_living`.

## Заставка встроена в экран запуска

Отдельного чёрного оверлея больше нет. Анимация идёт прямо внутри `#loginView`:
пыль слетается в центр, вспышка, кольцо — и после этого проявляется обычный
launch-экран с логотипом и кнопкой «Открыть плеер». Если плеер уже запущен и
экрана запуска нет, заставка не показывается вовсе. Пропуск — клик или клавиша.

# v1.2.1 — исправление: обложка/рамка/круги не реагировали на бит

## Причина

`bass` считался по фиксированной формуле: `(среднее по первым 6 бинам / 255) × 1.65`.
На любом треке со сколько-нибудь заметным низом среднее значение бинов уже
давало ×1.65 больше единицы — и `bass` почти всегда упирался в потолок 1.00,
даже на спокойных треках.

Дальше это ломало сразу всё, что завязано на удар:

* **детектор бита** сравнивает текущий бас со средним за последние ~0.8 c
  (`bass > avg * 1.3`) — если и текущее значение, и среднее одинаково прижаты
  к 1.00, «более громкого, чем обычно» момента просто не существует, событие
  бита никогда не срабатывает;
* обложка дышит и рамка светится напрямую от `--lv-bass`, а раз оно
  константа — движения нет;
* круги из мини-обложки, вспышка и толчок панели вообще навешаны на событие
  бита — событие не приходит, эффектов не видно.

Это не зависело от того, агрессивный трек или нет: не хватало не «энергии»,
а *запаса сверху* в шкале 0..1.

## Исправление — автонормализация (AGC)

Вместо фиксированного множителя каждая полоса (bass/mid/hi/rms) теперь следит
за своим недавним пиком: пик захватывается мгновенно, дальше медленно
«остывает» примерно 5–8 секунд, а текущее значение выражается как доля от
этого потолка. Так и тихий, и громкий трек дают полный диапазон 0..1 с
настоящими перепадами, а не наклеенную единицу.

На проверочном сигнале с умеренными ударами раз в 0.5 с: раньше bass сразу
шёл к 1.00 и там оставался; теперь колеблется в диапазоне примерно 0.25–0.73,
и детектор поймал 8 ударов за 4 секунды — как и должно быть на такой частоте.

Текущий потолок AGC виден в диагностике (Настройки → Живой интерфейс →
Диагностика реактивности) отдельной строкой — если он не двигается со
временем, стоит прислать скриншот панели.

## Про авто-деградацию качества (quality)

Отдельно от звука в слое есть защита от подвисаний: он сам считает средний
интервал между кадрами, и если он держится дольше ~34 мс (то есть меньше
~30 fps) дольше 2.5 секунды подряд, слой ступенчато урезает себя:

* `quality 0` — всё включено (частицы, орбиты, ripple-волны);
* `quality 1` — частиц заметно меньше (90 вместо 340), ripple и орбиты выключены;
* `quality 2` — канвас полностью пуст, работают только CSS-эффекты.

Если через ~8 секунд кадры выправляются — уровень откатывается обратно.
Это защита от «зависания», а не причина отсутствия эффектов — текущий
уровень виден в диагностике строкой `качество N`. Если у тебя `quality`
всегда 0, а кругов всё равно нет — дело было не в этом, а в баге с bass
выше (уже исправлен).
